# PRD: somm

> 에이전트 스킬을 위한 **앱스토어 + 시험 착용실** 데스크톱 앱
> 버전: 초안 v0.1 · 2026-11-05 · 작성: joon + Claude

---

## 1. 문제

- Claude Code, Codex 사용자는 GitHub, skills.sh, 공식 마켓 등 **여기저기 흩어진 스킬**을 직접 찾아야 한다.
- **깔기 전에는 효과를 알 수 없다.** README의 "토큰 80% 절감" 같은 수치는 대부분 만든 사람이 직접 잰 것이다.
- **보안 위험이 크다.** Snyk가 스킬 3,984개를 분석한 결과 76개는 악성으로 확인됐고, 13.4%는 치명적 문제, 36.8%는 보안 문제가 있었다.
- 스킬을 여러 개 깔면 **서로 충돌**한다. 예를 들어 superpowers와 gstack은 역할이 겹친다.

## 2. 해결책 (한 줄)

여러 출처의 스킬을 한곳에서 둘러보고, **내 프로젝트 복사본에서 스킬 없음/있음을 A/B로 돌려 효과와 보안을 확인한 뒤**, Claude Code나 Codex에 클릭 한 번으로 설치한다.

## 3. 타깃

- 1차: Claude Code와 Codex를 쓰는 글로벌 개발자 (UI는 영어 우선, 한국어 지원)
- 2차(나중): Cursor, Antigravity, Orca, Paseo 사용자, 그리고 팀과 기업

## 4. 경쟁과 차별점

| 경쟁 | 하는 것 | 없는 것 |
|---|---|---|
| Skills Manager, Skiller (데스크톱, 무료) | 둘러보기, 여러 에이전트에 설치·동기화 | 테스트, 보안 검사, 추천 |
| skills.sh, agent-skills.cc (웹 디렉토리) | 목록, 설치 수 순위 | 실행 검증 |
| Snyk Agent Scan, SkillScan (보안) | 정적 검사, 샌드박스 검사 | 효과 측정, 스토어 |
| skill-eval, NVIDIA SkillEvaluator (A/B) | 스킬 제작자용 CLI 평가 | 일반 사용자용 GUI |

**차별점:** 스토어 + **내 프로젝트에서 미리 돌려 보는 A/B 테스트** + 보안 검사 + 원클릭 설치를 하나로 묶은 GUI.

### 포함

- Claude Code와 Codex 외 다른 에이전트 지원

## 6. 화면

### 6.1 스토어
- 카드 그리드: 이름, 한 줄 설명, 출처 배지, ⭐ 스타 또는 ⬇ 설치 수, 지원 에이전트 아이콘, 보안 등급
- 상단 탭: **Hot** (일 / 주 / 월 / 연) · **All-time** · **Curated**
- 필터: 카테고리, 지원 에이전트(Claude Code / Codex), 출처, 라이선스, 보안 등급
- `⌘K` 검색창 (Raycast 스타일)
- UI 레퍼런스: Raycast Store(톤, 검색), Product Hunt(기간별 순위), LM Studio("내 환경에 맞는지" 표시)

### 6.2 상세
- README 요약(LLM이 3줄로 정리), 포함된 스킬·커맨드·스크립트·훅 목록
- 정적 보안 검사 결과(즉시 표시), 스타·설치 수 추이, 저장소 정보
- 버튼: **[테스트하기]** / **[바로 설치]** (바로 설치는 보안 등급 B 이상일 때만 활성화)

### 6.3 테스트 실행
- 왼쪽 패널: 스킬 설명. 무엇을 하는지, 언제 실행되는지, 구성 파일 트리
- 오른쪽 패널: 실시간 로그. 에이전트가 읽은 파일, 실행한 명령, 네트워크 요청
- 상단: A/B 진행 바 (Baseline ▶ / With Skill ▶)
- 보안 경고는 발생 즉시 토스트로 표시

### 6.4 결과
- 비교 표: 토큰, 시간, 테스트 통과, 변경 파일 수 (A vs B, 차이를 %로)
- **한 줄 판정**. 예: "리뷰 품질은 올랐지만 토큰을 38% 더 씁니다. 큰 PR에서만 추천."
- diff 보기, 보안 리포트
- **[공유 카드 만들기]**: SNS용 PNG 이미지(바이럴 장치)
- **[설치]**: 대상 에이전트와 범위(전역/프로젝트)를 고른다

### 6.5 설치 관리
- 감지된 에이전트별로 설치된 스킬 목록 (이 앱 밖에서 설치한 것도 표시)
- 켜기·끄기, 삭제, 업데이트 확인(콘텐츠 hash 비교)
- 충돌 경고(MVP는 간단한 규칙 기반): 같은 이름, 같은 커맨드, 역할이 겹치는 방법론 스킬

## 7. 기술 결정

### 7.1 기술 스택 (기준: 가볍고, 에이전트가 만들고 고칠 때 토큰이 적게 드는 것)

| 영역 | 선택 | 이유 |
|---|---|---|
| 앱 셸 | **Tauri 2** | 설치 파일 약 10MB(Electron은 약 100MB 이상). 공식 플러그인(shell, fs, sql, http)으로 Rust 코드를 최소화한다 |
| 프론트 | **Svelte 5 + TypeScript** | 같은 화면을 React보다 짧은 코드로 만들 수 있어 읽기와 수정에 드는 토큰이 적다 |
| 스타일 | **Tailwind CSS** | 별도 CSS 파일 없이 마크업 안에서 끝난다 |
| 로컬 DB | **SQLite** (tauri-plugin-sql) | 스토어 캐시, 테스트 기록 |
| 로직 위치 | **TypeScript 중심.** Rust는 플러그인 등록과 꼭 필요한 명령만 | 언어를 하나로 유지해 컨텍스트를 줄인다 |

**토큰 절약 규칙** (AGENTS.md에 넣는다)
- 파일당 300줄 이하, 기능별 폴더(`features/store`, `features/test-runner`…)
- 외부 의존성 최소화, 큰 UI 라이브러리 사용 금지
- 모든 외부 연동은 `adapters/` 아래 인터페이스 하나로 감싼다

### 7.2 스토어 데이터 수집

**구조: GitHub Actions 크롤러 → 정적 `index.json` → 앱이 받아 감**
- 앱 안에서 매번 크롤링하지 않는다. 별도 공개 저장소의 GitHub Actions가 하루 1~4회 실행되어 `index.json`과 일별 스냅샷을 GitHub Pages나 Releases에 올린다. 서버 비용은 0원이다.
- 이유: skills.sh API는 Vercel OIDC 인증이 필요해서 데스크톱 앱에서 직접 부르기 어렵고, GitHub API는 사용자마다 호출 한도가 있다.

**출처** (어댑터 단위로 하나씩 추가)
1. skills.sh API: `installs`, `trending`, `hot`, audit (Actions가 Vercel 함수를 통해 호출하거나, 공개 데이터로 대체)
2. GitHub 검색: `SKILL.md` 파일, `agent-skills` / `claude-skills` 토픽, 스타 수
3. 공식 마켓: `anthropics/claude-plugins-official`의 marketplace.json, OpenAI Codex 스킬 카탈로그
4. 기타: ClawHub, awesome-* 목록

**순위 규칙**
- 기본 지표는 설치 수(있을 때)이고, 없으면 GitHub 스타
- 일·주·월·연 Hot = 해당 기간의 증가량(일별 스냅샷의 차이). 출처별로 단위가 달라서 정규화 점수로 합친다
- 중복 처리: 같은 저장소나 같은 콘텐츠 hash면 합치고, 포크는 숨긴다

### 7.3 샌드박스 (제안: 2단계 자동 선택)

| 단계 | 방식 | 언제 | 장단점 |
|---|---|---|---|
| **Lite** | git worktree + 격리된 설정 폴더 | 정적 검사 A·B 등급, 스크립트 없는 순수 마크다운 스킬 | 빠르고 Docker가 필요 없다. 대신 OS 수준 격리는 아니다 |
| **Secure** | Docker 컨테이너 | 스크립트·훅·MCP가 포함되거나 C 등급 이하, 또는 사용자가 선택할 때 | 강하게 격리된다. 대신 Docker가 필요하고 느리다 |

**공통 장치**
- **설정 격리:** 실제 `~/.claude`, `~/.agents`를 건드리지 않는다. Claude Code는 `CLAUDE_CONFIG_DIR`, Codex는 `CODEX_HOME`으로 임시 폴더를 지정하고, 그 안에 테스트할 스킬만 둔다. *(환경 변수 이름과 동작은 구현 전에 확인)*
- **허니팟(canary):** 가짜 `.env`, 가짜 SSH 키, 가짜 API 토큰을 심어 두고, 읽거나 외부로 보내면 즉시 "악성" 판정한다
- **네트워크 (Secure):** 기본으로 LLM API 도메인만 허용하고, 그 밖의 접속은 기록한 뒤 차단한다
- **인증 정보:** 사용자의 실제 키는 해당 API 도메인으로만 나가게 한다. Secure 모드에서는 키를 환경 변수로만 주입한다
- **Docker가 없으면:** Lite로만 실행하되, 스크립트가 들어 있는 스킬은 "정적 검사만 가능"으로 표시한다

### 7.4 에이전트 연동

| | Claude Code | Codex |
|---|---|---|
| 스킬 경로 (전역) | `~/.claude/skills/<name>/SKILL.md` | `~/.agents/skills/<name>/SKILL.md` |
| 스킬 경로 (프로젝트) | `.claude/skills/` | `.agents/skills/` |
| 플러그인 | `claude plugin install …` | `codex plugin …` (지원 범위 확인) |
| 헤드리스 실행 | `claude -p "<task>" --output-format stream-json` | `codex exec --json "<task>"` |
| 지표 수집 | stream-json의 usage 필드 | JSON 이벤트의 토큰 사용량 |

- 감지: CLI가 PATH에 있는지와 설정 폴더가 있는지 확인
- 설치: 기본은 **복사**(원본 보존, 업데이트 시 hash 비교)이고, 고급 옵션으로 심볼릭 링크를 지원한다
- 설치 전후로 설정 폴더를 백업하고, 한 번에 되돌릴 수 있게 한다
- *(CLI 플래그와 출력 형식은 구현 시점의 최신 문서로 확인)*

### 7.5 A/B 테스트

**흐름**
1. 대상 프로젝트를 고른다 (없으면 내장 데모 저장소: TS 하나, Python 하나)
2. 테스트 작업을 정한다. 에이전트가 스킬 설명과 프로젝트를 보고 **작업 후보 3개**를 제안하고 사용자가 고른다. 직접 입력도 가능하다
3. 같은 작업을 **A(스킬 없음)**와 **B(스킬 있음)**로 각각 새 worktree에서 실행한다
4. 실행 옵션 (서로 별개로 고른다)
   - **Auth:** Subscription(기본, 로그인된 `claude`/`codex` 그대로) / Isolated(API 키, `claude --bare` + `--max-budget-usd`, Codex는 `CODEX_API_KEY`)
   - **Runs:** Quick(기본, A/B 각 1회) / Thorough(A/B 각 3회 평균 + 편차 표시)

**지표**

| 지표 | 수집 방법 |
|---|---|
| 토큰 (입력·출력·합계) | 에이전트의 JSON 출력 |
| 시간 | 실행 시작부터 종료까지 |
| 테스트 통과 | 프로젝트의 테스트 명령을 자동 감지(`package.json`, `pytest` 등)해서 실행 후 통과·실패 수 집계 |
| 변경 파일 | `git diff --stat` (파일 수, 추가·삭제 줄 수) |
| **한 줄 판정** | 위 지표와 두 diff를 LLM에 넘겨 1문장 판정과 추천 등급(추천 / 조건부 / 비추천)을 받음 |

- 판정은 사용자가 지정한 에이전트(Claude Code 또는 Codex)가 내린다. 비용을 아끼기 위해 작은 모델 옵션도 둔다.

### 7.6 보안 검사 (제안: 3겹)

| 단계 | 내용 | 시점 |
|---|---|---|
| **1. 정적 검사** (직접 구현) | `curl \| bash`, `eval`, base64·난독화, 위험 명령(`rm -rf`, `chmod`), 외부 URL 다운로드, 비밀값 접근 패턴, 훅과 MCP 설정, 프롬프트 인젝션 문구("이전 지시 무시" 등), 이름이 비슷한 사칭 저장소 | 상세 화면을 열 때 즉시 |
| **2. 외부 검사 연동** (선택) | skills.sh audit 결과 표시, Snyk `agent-scan` CLI가 설치돼 있으면 함께 실행 | 상세 화면과 테스트 전 |
| **3. 동적 관찰** | 샌드박스 실행 중 worktree 밖 파일 쓰기, 네트워크 요청, 하위 프로세스 실행, 허니팟 접근을 기록 | 테스트 중 |

- **등급 A~F:** 정적 검사 + 외부 검사 + 동적 관찰 결과를 합산한다. F(허니팟 접근, 악성 확정)는 설치를 차단한다.
- 규칙은 YAML 파일로 관리해서 커뮤니티가 기여할 수 있게 한다.

## 8. 성공 지표 (MVP)

- GitHub 스타, 다운로드 수
- 주간 활성 사용자 중 테스트를 1회 이상 실행한 비율

- 공유 카드 생성 수 (바이럴 지표)

## 10. 리스크와 미정 사항

- [ ] LLM 결과는 매번 달라서 1회 A/B의 신뢰도가 낮다 → Runs: Thorough(3회 평균 + 편차), 결과에 신뢰도 표시
- [ ] 테스트하면 토큰이 두 배로 든다 → 실행 전에 예상 비용을 표시, 작은 모델 옵션
- [ ] Docker 안에서 Claude Code·Codex를 어떻게 인증할지 (구독 로그인 vs API 키)
- [ ] skills.sh API 인증 방식(Vercel OIDC)을 크롤러에 어떻게 붙일지
- [ ] 각 출처의 이용 약관과 재배포 정책 확인
- [x] 이름 확정: 프로젝트 **somm**, 캐릭터 **Sir Somm** (외눈 안경 소믈리에). 결과 문구 `// somm: pairs well`, 거절 `// somm: corked`

## 11. (내부) 이 앱을 만드는 방식

> 이 섹션은 joon이 이 앱을 **개발하는 과정**에 관한 것이다. 앱 사용자가 쓰는 기능이 아니다.
